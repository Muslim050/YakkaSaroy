# Yakka Saroy — сайт ресторана и банкетного зала

Лендинг с проверкой свободных дат и онлайн-бронированием, кабинет гостя и админка для менеджеров. Next.js 16 (App Router, Cache Components), Tailwind CSS 4, shadcn/ui на Base UI, TypeScript.

## Запуск

Данные хранятся в Postgres (Neon, подключён через Vercel Marketplace к проекту `yakkasaroy`). Переменные подключения берутся из Vercel:

```bash
pnpm install
vercel env pull .env.local
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Сайт откроется на http://localhost:3000. `db:migrate` создаёт таблицы, `db:seed` добавляет демо-данные.

### Команды базы

| Команда | Что делает |
| --- | --- |
| `pnpm db:generate` | создаёт файл миграции в `drizzle/` после правки `src/db/schema.ts` |
| `pnpm db:migrate` | применяет миграции к базе из `.env.local` |
| `pnpm db:seed` | заменяет демо-брони, добавляет демо-администраторов и каталог, если их нет |
| `pnpm db:clear-demo` | удаляет только демо-брони, перед запуском сайта |

Настоящие заявки скрипты не трогают: удаляются только строки с пометкой демо, а демо-брони обходят время, уже занятое настоящими.

## Разделы

| Адрес | Кто | Что там |
| --- | --- | --- |
| `/` | все | сайт: залы, меню, галерея, свободные даты, заявка |
| `/login` | все | вход: вкладка «Гость» или «Администратор», слева план залов с занятостью на сегодня |
| `/cabinet` | гость | свои торжества: этапы подготовки, дегустация, предоплата и остаток, правка гостей и пожеланий, отмена заявки |
| `/admin` | администратор | обзор: новые заявки, ближайшие 7 дней, предоплаты, загрузка залов, дегустации |
| `/admin/bookings` | администратор | все брони с фильтрами по статусу и залу, поиск, карточка брони, новая бронь по телефону |
| `/admin/calendar` | администратор | месяц по залам: занятые и свободные дневные и вечерние торжества |
| `/admin/clients` | администратор | клиенты по номеру телефона и их брони |
| `/admin/catalog` | администратор | каталог программы: варианты меню, оформления, шоу, торта и съёмки с ценами, фото и видео |

Устройство повторяет платформу Global Expo (тёмная верхняя панель с разделами, формы в боковой панели справа, доступ по ролям), но ролей две: администратор и гость.

### Как входит гость

Пароля у гостя нет. После заявки на сайте он получает номер брони вида `YS-1234` и входит по телефону, указанному в заявке, и этому номеру. Видит только брони со своим телефоном. До предоплаты может изменить число гостей и пожелания или отменить заявку, после предоплаты изменения идут через менеджера.

### Программа торжества

У каждого банкета есть программа: меню, оформление зала, шоу и музыка, торт, фото и видео. У вариантов есть фото и видео: видео играет без звука, когда карточка на экране, а по нажатию открывается крупно со звуком. Справа сводка «Ваш выбор» с итоговой суммой.

- Гость выбирает на странице `/cabinet/program/[id]`, до предоплаты. После предоплаты программа только для просмотра.
- Администратор открывает ту же страницу из карточки брони (`/admin/bookings/[id]/program`) и может менять её, пока торжество не прошло и бронь не отменена.
- Каждое изменение пишется в историю брони одной строкой.
- Варианты, цены и медиа менеджер ведёт сам в разделе «Каталог» (`/admin/catalog`): название, описание, состав, цена («входит в стоимость», «за гостя» или фиксированная), порядок, скрыть или показать, фото и видео. Каталог хранится вместе с бронями; первый раз он заполняется из `src/lib/programSeed.ts` (фото с Unsplash, видео с Mixkit), замените их на свои съёмки.
- Скрытый или удалённый вариант пропадает из выбора, но в бронях, где его уже выбрали, остаётся с пометкой «больше не предлагается» и по старой цене. В меню и оформлении всегда должен остаться хотя бы один вариант.
- Свои фото и видео загружаются прямо из браузера в Vercel Blob, поэтому большие видео не упираются в лимит 4,5 МБ на запрос; обложку для видео браузер делает сам. Без подключённого хранилища раздел предлагает добавить файл по ссылке.

### Статусы брони

`Новая заявка` → `Дата придержана` → `Предоплата внесена` → `Проведено`, а также `Отменена`. Каждое изменение пишется в историю брони с отметкой, кто его сделал. Заметку менеджера гость не видит.

## Демо-доступы

Демо-данные создаёт `pnpm db:seed`: брони на 60 дней назад и 120 вперёд, два администратора и три брони демо-гостей.

| Вход | Логин или телефон | Пароль или номер брони |
| --- | --- | --- |
| Администратор | `admin` | `admin` |
| Администратор | `manager` | `manager` |
| Гость, две брони | `+998 90 123 45 67` | `YS-2026` или `YS-2027` |
| Гость, новая заявка | `+998 93 555 12 34` | `YS-7341` |

Перед публикацией выполните `pnpm db:clear-demo`, задайте `ADMIN_PASSWORD` и удалите демо-аккаунт `manager` из таблицы `admin_users`. Если `ADMIN_PASSWORD` задан, учётная запись `admin` входит только с ним и создаётся сама при первом входе на пустой базе.

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `AUTH_SECRET` | ключ подписи сессий, 32+ символа. В продакшене без него вход не работает. Сгенерировать: `openssl rand -base64 32` |
| `DATABASE_URL`, `DATABASE_URL_UNPOOLED` | подключение к Neon Postgres. Появляются сами от интеграции Neon в проекте Vercel; локально: `vercel env pull .env.local` |
| `ADMIN_PASSWORD` | пароль учётной записи `admin` вместо демо-пароля |
| `BLOB_READ_WRITE_TOKEN` | загрузка фото и видео в каталоге. Появляется сама, когда к проекту на Vercel подключено публичное хранилище Blob (Storage → Create → Blob, доступ Public); локально: `vercel env pull .env.local` |

## Что внутри

- `src/lib/data.ts` — контент: залы, цены за гостя, меню, фото, контакты.
- `src/lib/bookings.ts` — статусы, форматирование телефонов и сумм, расчёт стоимости банкета вместе с программой.
- `src/lib/program.ts` — типы каталога программы, выбор по умолчанию, проверка выбора и расчёт стоимости; `src/lib/programSeed.ts` — первоначальный каталог.
- `src/lib/store.ts` — все обращения к данным: брони, клиенты, каталог, администраторы. Страницы и API ходят только через него.
- `src/db/schema.ts` — таблицы Postgres; `drizzle/` — миграции; `src/db/demo.ts` и `scripts/seed.ts` — демо-данные.
- Двойную бронь банкета отсекает сама база: уникальный индекс на зал, дату и время для неотменённых броней. Лимит в 24 столика на час ресторана проверяется в транзакции под блокировкой.
- Попытки входа считаются в таблице `login_attempts`, поэтому лимит работает на всех экземплярах сервера.
- «Сегодня» везде считается по Ташкенту (`src/lib/time.ts`), потому что серверы Vercel работают в UTC.
- `src/lib/session.ts`, `src/lib/auth.ts` — подписанная httpOnly-cookie и проверка роли. Каждая страница и каждый API-маршрут проверяют сессию на сервере.
- `src/app/api/auth/*` — вход и выход, не больше 5 неудачных попыток за 15 минут.
- `src/app/api/admin/bookings` — создание и правка броней администратором.
- `src/app/api/admin/catalog` — правка каталога программы; `catalog/upload` выдаёт браузеру токен для загрузки в Vercel Blob.
- `src/app/api/cabinet/bookings/[id]` — правка и отмена гостем только своих броней.
- `src/app/api/availability`, `src/app/api/bookings` — занятость и заявка с сайта.

## Что заменить перед запуском

1. **Фото.** Сейчас стоят картинки с Unsplash. Положите свои в `public/` и замените ссылки в `src/lib/data.ts` и `src/components/Hero.tsx`, `About.tsx`.
2. **Телефон.** В `CONTACTS` в `src/lib/data.ts` стоит заглушка `+998 71 000 00 00`.
3. **Цены и меню.** Там же, в `HALLS` и `MENU`.
4. **Отдельная база для разработки.** Сейчас разработка и продакшен работают с одной базой Neon. Перед запуском сайта стоит завести для разработки отдельную ветку базы в Neon.
5. **Вход гостя по SMS.** Сейчас гость входит по номеру брони. Надёжнее отправлять одноразовый код в SMS (Eskiz или Play Mobile) и проверять его в `src/app/api/auth/login`.
6. **Уведомления.** Новая заявка только сохраняется. Добавьте отправку в Telegram или на почту менеджера после `createBooking`.
